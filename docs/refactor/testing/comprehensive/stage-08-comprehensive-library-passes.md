# Stage 8 — Comprehensive per-library passes

See [00-overview.md](00-overview.md) §4 for why this isn't "test
everything." Each library's stage-04* document already named its first
pass's scope explicitly (usually one file, sometimes one function); this
document is the follow-up plan for going meaningfully deeper, library by
library, plus `kfx_sim`'s promised per-cluster breakdown in full.

## 1. What "comprehensive enough" means, absent a coverage number

Stage-05 deliberately defers a coverage-percentage floor. Until that
number exists and has a real baseline, use a cheaper per-library
checklist instead — for each library, comprehensive-enough means:

1. Every function stage-04*'s own document flagged as "a reasonable next
   candidate" (most of them named at least one) actually has a test.
2. At least one function per *major internal cluster* (a library's own
   natural file groupings — `kfx_sim`'s `map_*`/`thing_*`/`creature_*`/
   `room_*`/`player_*`, `kfx_config`'s `config_*` loaders, …) is covered,
   not just whichever cluster happened to contain the easiest pilot
   function.
3. At least one test per library exercises pattern B (a callback-struct
   fake) where the library owns or calls through one — stage 1–4's pilots
   were deliberately chosen to *avoid* pattern B wherever possible to
   prove the harness cheaply first; a comprehensive pass is exactly where
   that avoidance should stop, since the callback-struct seams are a
   real, load-bearing part of this codebase's design and are currently
   the least-tested part of it precisely because they were the hardest
   pilot candidates.

## 3. `kfx_sim`'s per-cluster breakdown

The library-split plan's own precedent for a library this size: stage 6
(the original `kfx_sim` extraction) got a main document plus three
appendices (`stage-06a`/`b`/`c`) rather than one document trying to cover
all 83 files. This plan follows the same shape — five clusters, matching
`kfx_sim`'s own natural file-prefix groupings. **First pass landed across
all five together**, one foundational-accessor layer per cluster rather
than one cluster taken deep — see
[stage-08b-kfx-sim-clusters.md](stage-08b-kfx-sim-clusters.md) for the
full account (25 new tests, three genuine cross-cluster asymmetries found
by reading each cluster's actual accessor bodies rather than assuming
family resemblance).

rollout in this plan made.

## 4. Exit criterion

Not "all eight libraries fully covered" — that's not this document's
claim. Per library: §1's three-point checklist satisfied, confirmed
against a real build and `ctest` run the same way every stage-04*
document already did, with `check_layering.py`/`check_layering_symbols.py`
reconfirmed unaffected after each addition (the standing verification
habit every prior stage in this whole plan has followed without
exception). `kfx_sim` additionally needs at least one landed test per
cluster in §3 before being called "comprehensively" rather than
"pilot-only" covered.
